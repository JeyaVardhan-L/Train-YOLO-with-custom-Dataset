| | |
| :-- | :-- |

## Results

Validation split of 1,778 images:

| Evaluation | Precision | Recall | mAP@50 | mAP@50-95 |
| :-- | :-: | :-: | :-: | :-: |
| Fresh validation run, `weights/best.pt` (2026-11-10) | 0.887 | 0.850 | 0.899 | 0.557 |
| Training log, run 2, last epoch (57) | 0.888 | 0.844 | 0.900 | 0.565 |
| Training log, run 1, last epoch (35) | 0.873 | 0.833 | 0.888 | 0.550 |

In run 2 the best mAP@50-95 in the log is at epoch 54 (0.5674), so `best.pt` is most likely the epoch-54 weights (not confirmed by opening the checkpoint). The fresh run gives a slightly lower mAP@50-95 than the log (0.557 against 0.565); the cause was not investigated (software version and hardware are the likely reasons).

Per class (fresh run):

| Class | Images | Instances | Precision | Recall | mAP@50 | mAP@50-95 |
| :-- | :-: | :-: | :-: | :-: | :-: | :-: |
| Aircrafts | 754 | 977 | 0.887 | 0.868 | 0.902 | 0.588 |
| Bird | 262 | 1,159 | 0.867 | 0.789 | 0.864 | 0.428 |
| Drone | 767 | 958 | 0.906 | 0.895 | 0.931 | 0.654 |

Inference time reported by Ultralytics during the validation runs on the same CPU was 258 ms per image in one run and 509 ms in another (the machine was busy during the second). Treat CPU speed figures as rough.

**Caveat:** 173 of the 1,778 validation images (9.7%) share a source photo with a training image, so these scores are probably optimistic. See [chapter 4](../docs/04-split-without-leaking.md).
